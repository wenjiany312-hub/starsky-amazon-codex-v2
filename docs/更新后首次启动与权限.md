# 更新后首次启动与权限

首次安装或旧版本迁移时，星空只为自己的 `~/.starsky-codex` 绝对路径登记写权限，写入前备份配置；不改变沙盒模式、审批模式或网络权限。旧沙盒配置追加 `sandbox_workspace_write.writable_roots`；新版权限档使用独立的文件权限规则，不能与旧设置混写。

新版已有自定义工作权限档时，仅增加星空目录这一项，保留原限制。使用内置 `:workspace` 档时，生成继承原档的 `starsky-workspace`（有重名时附短后缀），请在 Codex 权限菜单选择一次；脚本不会自动切换默认档。只读档或明确禁止星空目录写入的规则保留，按宿主批准的单次权限处理。

旧用户首次进入修复版时，入口会在宿主允许的情况下发起一次权限申请，说明要登记星空目录和固定知识库入口。请核对说明后选择允许；拒绝时停止，保留旧版和数据。宿主禁止申请权限时，请在系统终端运行修复版 `locked/git_unlock.py --prepare-sandbox`，使用原安装记录中的专用 Python。

完成后完全退出并重新打开 Codex，再开新会话。配置不保证对已经运行的会话即时生效。后续解锁只写星空自己的目录，三个知识库从固定启动器读取当前版本，不逐版改 Codex 配置。

如果看到“需要允许星空写入用户目录”，先按提示批准单次权限请求；没有弹出时回复“帮我解决这个权限问题，继续启动星空”。不要关闭沙盒，不要仅为该错误重装插件。

只读模式、组织策略或自定义权限配置仍可能要求单次批准；星空不会修改这些设置，也不会声称已获得当前会话没有的权限。

Claude Desktop 使用宿主原生 command 更新，在原生安装步骤完成完整插件登记；不向 Codex 配置添加 Claude 路径，不让业务会话负责首次解锁。两端共用签名、许可和安装记录事务代码，但不能把 Codex 的沙盒设置套到 Claude 上。

## 给现有用户的通知

更新后首次“启动星空”若提示需要写入用户目录，请按宿主说明允许一次。没有弹出请求时，可回复“帮我解决这个权限问题，继续启动星空”；如果当前环境禁止申请权限，按提示在系统终端完成一次权限迁移。迁移完成后重开 Codex，后续更新使用固定知识库入口，减少重复配置和权限中断。已装版本、授权和产品资料保留。

权限错误不等于授权失效；仍需按实际错误区分。Mac 与 Windows 默认沙盒的无弹窗升级，必须以对应设备的实测结果为准。

# Codex 正式版 · 年度会员更新与续期

仅提供 365 天（1 年）年度会员。按北京时间计算，包含签发当天，至授权到期日当天结束；具体日期以作者签发结果为准。

## 更新操作

在 Codex 的 **插件 → 市场** 找到「星空 Codex 正式版」对应市场，点击 **升级（Upgrade）**。完成后新开会话，输入 **启动星空**。升级会拉取正式版发行文件，并根据本机授权解锁对应更新。

新版必须由作者向本正式版通道发布，并为有效会员提供对应档位的更新凭证。首次安装前仍需取得本机 Key；后续有效期内更新无需逐版换 Key。下载文件、拉取市场和成功解锁是不同步骤，以新会话实际加载的版本为准。

## 到期、续期与设备绑定

到期后已安装内容保留，后续新版本需续期。续期由作者延长原设备的会员权益并同步更新凭证；一机一码，不支持更换电脑；不能沿用另一台电脑的码。

## 正式版与测试版

本仓只发布付费正式版；测试版的 Key、登记表和发行通道独立。测试授权不包含正式版，不能因为测试通道更新或停止维护而自动转为正式会员。

## 购买与设备规则

**一机一码，不支持更换设备，多台电脑需分别购买；购买后不接受退款，请确认需求后再购买；但如果是产品本身无法按说明正常使用等质量问题，作者会协助解决，不受这一条限制。** 购买前请确认产品、版本档、系统环境与所绑定的电脑。

详见 [使用条款](使用条款.md)。

## 更新失败

若「升级（Upgrade）」后未取得新版，可运行安装包里的「检查新版」，并在新会话核对实际加载版本。

先确认产品、版本档、当前授权日期与网络状态。只拉取到文件但解锁失败时，保留旧版本和业务资料，将已脱敏错误发给作者；不要发送完整 Key、配置密钥或店铺数据。没有可确认的新版本时继续使用当前安装版本。


## 2026-10-17 更新说明

# 更新后首次启动与权限

首次安装或旧版本迁移时，星空只为自己的 `~/.starsky-codex` 绝对路径登记写权限，写入前备份配置；不改变沙盒模式、审批模式或网络权限。旧沙盒配置追加 `sandbox_workspace_write.writable_roots`；新版权限档使用独立的文件权限规则，不能与旧设置混写。

新版已有自定义工作权限档时，仅增加星空目录这一项，保留原限制。使用内置 `:workspace` 档时，生成继承原档的 `starsky-workspace`（有重名时附短后缀），请在 Codex 权限菜单选择一次；脚本不会自动切换默认档。只读档或明确禁止星空目录写入的规则保留，按宿主批准的单次权限处理。

旧用户首次进入修复版时，入口会在宿主允许的情况下发起一次权限申请，说明要登记星空目录和固定知识库入口。请核对说明后选择允许；拒绝时停止，保留旧版和数据。宿主禁止申请权限时，请在系统终端运行修复版 `locked/git_unlock.py --prepare-sandbox`，使用原安装记录中的专用 Python。

完成后完全退出并重新打开 Codex，再开新会话。配置不保证对已经运行的会话即时生效。后续解锁只写星空自己的目录，三个知识库从固定启动器读取当前版本，不逐版改 Codex 配置。

如果看到“需要允许星空写入用户目录”，先按提示批准单次权限请求；没有弹出时回复“帮我解决这个权限问题，继续启动星空”。不要关闭沙盒，不要仅为该错误重装插件。

只读模式、组织策略或自定义权限配置仍可能要求单次批准；星空不会修改这些设置，也不会声称已获得当前会话没有的权限。

Claude Desktop 使用宿主原生 command 更新，在原生安装步骤完成完整插件登记；不向 Codex 配置添加 Claude 路径，不让业务会话负责首次解锁。两端共用签名、许可和安装记录事务代码，但不能把 Codex 的沙盒设置套到 Claude 上。

## 给现有用户的通知

更新后首次“启动星空”若提示需要写入用户目录，请按宿主说明允许一次。没有弹出请求时，可回复“帮我解决这个权限问题，继续启动星空”；如果当前环境禁止申请权限，按提示在系统终端完成一次权限迁移。迁移完成后重开 Codex，后续更新使用固定知识库入口，减少重复配置和权限中断。已装版本、授权和产品资料保留。

权限错误不等于授权失效；仍需按实际错误区分。Mac 与 Windows 默认沙盒的无弹窗升级，必须以对应设备的实测结果为准。

## 3.0.20 起的权限处理

不再创建未选择的命名权限档，不自动设置全局 `default_permissions`，不改变沙盒、审批或网络策略。内置权限档按宿主规则申请单次解锁权限，不承诺每次无弹窗。已有明确选择的自定义权限档，仅为星空目录追加允许的路径规则；只读或显式禁止保持不变。

旧式客户端仅追加星空 `~/.starsky-codex` 的绝对路径到原有 writable_roots；新版不混写旧沙盒配置。写配置前先备份，保留原备注和其他设置。所有解锁入口都能识别该已知坏段，修复仍须获得当前环境允许的写权限。

旧用户升级后，入口会按需申请一次权限，登记固定知识库启动器并清理已知无效段。请核对理由后允许；拒绝或宿主禁止申请时停止，不绕过，按提示到系统终端处理。完成后完全退出并重开 Codex、新建会话。

日常解锁不逐版改知识库配置；三个知识库从固定启动器读取当前版本。若提示需要写入用户目录，请按宿主允许的单次权限请求处理。没有弹出时可回复「帮我解决这个权限问题，继续启动星空」，不要关闭沙盒或反复重装。

## 手动恢复与通知

先备份 ~/.codex/config.toml。仅当顶层没有 default_permissions，且两段原样仅含以下4行时，删除这4行：

```toml
[permissions."starsky-workspace"]
extends = ":workspace"
[permissions."starsky-workspace".filesystem]
"本机星空用户目录的绝对路径" = "write"
```

不要删除其他权限档、额外规则或已有默认值。已经自行修改、报其他配置错误时保留文件并联系作者，不套用此删除法。

授权、API、其他插件和产品资料保留。已用当前26.1013客户端的同一配置读取程序复现并验证修复；Mac实机GUI启动、更新后启动仍需分别验收，不能用CLI结果代替。

Claude Desktop 不向 Codex 配置添加权限档，不受这段Codex配置影响；Claude使用自身原生更新流程。
